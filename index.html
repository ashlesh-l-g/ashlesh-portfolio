01 BACKEND SYSTEMS

Task Management Service

A task management application built around explicit business rules and a layered backend architecture.

  • LIFECYCLE FSM Strict unidirectional state transitions: TODO → IN_PROGRESS → DONE. Illegal transitions are rejected at the service layer.
  • MODIFICATION LOCK Tasks in DONE state are immutably locked against payload mutations and status regressions.
  • SOFT DELETION Records are tombstoned via timestamp flagging; active queries exclude deleted rows while preserving audit trail integrity.
  • CACHE STRATEGY Read-aside Redis cache with TTL and key-based cache invalidation on any write or status change.

02 SYSTEMS PROGRAMMING

Dockerman

A Docker-inspired project written in C to explore Unix process management and the mechanics behind supervising workloads.

  • PROCESS SPAWNING Clones execution contexts using POSIX fork(), decoupling child execution from the parent supervisor.
  • IMAGE EXECUTION Invokes execvp() with file descriptor redirection of standard streams to per-service log sinks.
  • LIVENESS PROBING Non-destructive heartbeat validation via zero-signal kill(pid, 0) checks and PID registry tracking.
  • GRACEFUL TEARDOWN Dispatches SIGTERM with timeout-based fallback to SIGKILL to guarantee process cleanup.
  • C
  • POSIX System Calls
  • fork / exec
  • Signals & SIGTERM
  • PID Management
  • Linux / Unix

04 AI / APPLICATION ENGINEERING

Document Summary Assistant

A document processing application implementing structured text extraction, client-side OCR fallback, token-aware chunking, and AI synthesis.

Processes documents through a multi-tier pipeline: PDF stream parsing via PDF.js, browser-offloaded OCR fallback via Tesseract.js when text density falls below thresholds, hierarchical sentence chunking with token constraints, and provider abstractions accommodating models from NVIDIA NIM, Google Gemini, and Groq.
